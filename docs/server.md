# Общий серверный мир

[Открыть интерфейс](https://evo.valeriypolunovskiy.ru/). Один процесс хранит один
мир для всех посетителей. Вход, просмотр и команды требуют общего пароля;
посетители с этим паролем имеют одинаковые права. Закрытие вкладки не ставит мир
на паузу. Кнопки паузы, среды и сброса действуют на общий мир.

Телефон получает снимок состояния примерно два раза в секунду и рисует его.
Вычислений эволюции в этом интерфейсе нет. Нажатие на клетку запрашивает сведения
об организме. В скрытой вкладке опрос приостанавливается.

## Скорость

Показатель заданной скорости — цель в модельных часах за минуту реального
времени. Фактическая скорость показана отдельно и зависит от численности,
строения организмов и доступного процессорного времени. Скорость не меняет
порядок шагов модели. Расчёт последовательный, в отдельном рабочем потоке;
остальные ядра и GPU автоматически не используются.

На сохранённом мире с более чем 3000 организмами одинаковые 100 шагов заняли
17.75 с в изолированном контексте Node VM и 7.46 с при исполнении тех же скриптов
в обычном контексте V8. Полные наследуемые состояния и генератор случайных чисел
совпали. Это ускорение исполнения на одном сервере в 2.38 раза; сравнение с
телефоном не проводилось. Служба ограничена 80% одного процессорного ядра,
имеет низкий приоритет и лимит памяти 1 ГБ.

## Сохранения и перезапуск

Сохранение содержит весь мир, параметры, счётчики, наследуемые программы,
состояние генератора случайных чисел, историю и состояние паузы. Оно записывается
при запуске, каждые 30 секунд, после команды и при штатной остановке. Поэтому
аварийное выключение может потерять последние 30 секунд реального расчёта.

Запись атомарная с синхронизацией файла и каталога; сохраняется предыдущая
копия. Если текущая повреждена или отсутствует, читается предыдущая; повреждённый
файл откладывается отдельно. Если обе копии повреждены либо версия модели
несовместима, служба сообщает об ошибке. Новый мир вместо повреждённого
самопроизвольно не создаётся. Вымирание также не запускает заселение заново.
Перед явным сбросом сохраняется отдельный архив прежнего мира.

## Запуск своей службы

Требуется Node.js 22, внешние пакеты не нужны. Для пробного запуска:

```sh
mkdir -m 700 var
node server/auth.js var/auth.json
node server/main.js
```

Первая команда Node читает пароль из стандартного ввода до EOF; подайте точные
байты пароля без завершающего перевода строки через свой менеджер секретов.
Пароль не передавайте аргументом командной строки. Конфигурация содержит scrypt-хеш и
случайный ключ подписи сессий; держите её вне репозитория, с правами 600.
По умолчанию данные лежат в `var/`, а HTTP слушает `127.0.0.1:8797`.

Переменные окружения: `EVO_DATA_DIR`, `EVO_AUTH_FILE`, `PORT`, `EVO_ORIGIN`.
Последняя задаёт внешний HTTPS-адрес; команды проверяют точное совпадение Origin.
Для локального HTTP-теста задайте `EVO_ORIGIN=http://localhost:8797` и
`EVO_SECURE_COOKIE=0`; для публичного HTTPS оставьте защищённую cookie включённой.
Для публичного запуска нужен обратный прокси с HTTPS. Cookie сессии для HTTPS
имеет Secure, HttpOnly и SameSite=Strict; API требует авторизации, JSON и
ограничивает частоту входов и команд.

Шаблон пользовательской службы — [deploy/evolutioner.service](../deploy/evolutioner.service).
Перед установкой укажите свой путь к Node и каталогу проекта. Запуск через
`systemctl --user enable --now evolutioner.service`; для работы без входа
пользователя сервер должен разрешать linger.

При добавлении маршрута в существующий Cloudflare Tunnel утилита
`deploy/tunnel-route.py` поддерживает `plan`, `install`, `confirm`, `rollback`.
Она проверяет конфигурацию, сохраняет резервную копию и при установке запускает
таймер автоотката. Подтверждать маршрут следует после реальной внешней проверки
нового адреса и существующих сервисов.

## Обновление модели

Обновляйте код в отдельном каталоге выпуска. Контрольная сумма включает
`index.html`, серверную обвязку модели и загрузчик скриптов. Сохранения с другой
суммой не загружаются автоматически.

Для изменения только способа исполнения предусмотрен
`node tools/migrate-runtime.js OLD_ROOT NEW_ROOT CHECKPOINT`. Сначала остановите
службу и сохраните независимую копию текущего и предыдущего файлов. Утилита
продолжает один снимок на 30 шагов старым и новым исполнителями и разрешает
смену версии только при совпадении полных состояний. Она архивирует оригинал,
сохраняет прежний возраст мира и обновляет обе рабочие копии сохранения.
После этого переключите каталог выпуска, запустите службу и проверьте реальный
мир через интерфейс. При неудаче верните прежний каталог вместе с копиями
сохранений. Изменения правил эволюции требуют отдельной миграции.

## Проверка

```sh
node tools/build.js --check
node --test tests/*.test.js
```

23 проверки включают совпадение VM и обычного исполнения, отсутствие утечек
между мирами, точное продолжение в новом процессе, повреждение и отсутствие
сохранений, вход, ограничения команд и HTTP-перезапуск. Дополнительно на
развёрнутой службе проверены штатный перезапуск и аварийное завершение процесса;
в Chrome — общий мир в двух вкладках, продолжение без вкладок и ширины
320/390/1280 пикселей.
