# Стенд баланса

`sim.js` — headless-порт нового, **организм-центричного** ядра: единица симуляции
тело, а не клетка. Без DOM и canvas, запускается в Node. Нужен потому, что
экономику этой модели нельзя править вслепую — см. CLAUDE.md.

```
node sim.js 20000      # эволюционный прогон, сводка по нишам каждые N часов
node diag.js           # конкуренция подсаженных тел 4x4 против одноклеточных
node genestat.js       # средние И РАЗБРОС по генам во времени
node sexdiag.js        # 30 половых против 30 клональных с равного старта
PVIR=2.0 ICOST=0.06 node psweep.js   # паразиты: вирулентность и цена иммунитета
SEEDS=0 node sim.js 12000            # контроль: то же ядро без семян
```

## Воспроизводимость — `reset(24, seed)`

**`reset(n)` принимает ЧИСЛО КОЛОНИЙ, а не seed.** На этом уже споткнулись:
серия «пары прогонов с одинакового старта» оказалась шестью разными мирами,
потому что генератор был обычный `Math.random`. Теперь вторым аргументом идёт
seed, и стенд подменяет `Math.random` на `mulberry32` — одинаковый seed даёт
побитово одинаковый мир (проверено: два прогона по 800 часов дали
`708/900/3261` знак в знак). Сравнивать А и Б только так, методом общих
случайных чисел; после первой точки расхождения потоки всё равно разойдутся,
но старт и путь до неё общие.

`DORM=0` выключает покой зачатков (всхожесть снова детерминированная) — этим
снимался парный замер «спасает ли банк от вымирания». `killGuild(name)` выкашивает
нишу целиком: естественную гибель ниши в прогоне поймать трудно, а так условие
задаётся ровно (см. `wipe.js`-опыт в CLAUDE.md).

Диплоидность, икра и гаметы под флагами: `DIPLO=0` возвращает старую гаплоидную
рекомбинацию (монетка по каждому гену), `EGGS=0` — подсадку потомка вплотную у
травоядных и хищников вместо кладки, `GAM=0` — прежнее поведение «не нашёл
партнёра рядом — жди» без выпуска половых клеток (`GSPD`, `GLIFE` — скорость и
срок жизни гаметы).

Ветки сапротрофа переключаются флагами: `CONIDIA=0` убирает бесполое поле
плотности, `SPORESEX=0` — половые споры, `CINH=1` включает замеренный и
**не принятый** вариант «конидия наследует геном ближайшей грибницы».

Семена тоже параметризованы окружением: `SEEDS=0` выключает их целиком (нужно
для контрольного прогона — иначе «стало лучше» не с чем сравнить), `SUPK` —
дыхание семени, то есть срок покоя, `SRANGE` — предел разлёта, `SMAX` — потолок
банка семян, `SGL` — минимальный свет для всхода.

Вирулентность теперь эволюционирует сама: `VK` задаёт полунасыщение отдачи от
свирепости, `VMUT` — шаг её мутации при передаче, `PDMG` — цену вреда (именно она
тянет эволюционирующую свирепость вверх или вниз). `LIGHT` меняет плотность
хозяев — на нём проверяется предсказание «гуще хозяева, свирепее паразит».

`psweep.js` читает параметры паразита из окружения (`PVIR` общий множитель среды,
`ICOST` цена иммунитета, `PINF` заразность, `PSEED` частота новых штаммов,
`PDMG` базовый урон) — так одна и та же сборка ядра прогоняется под разными
режимами без правки файла.

`diag.js` намеренно выключает мутации: это тест не отбора, а экономики — если
готовые тела проигрывают одноклеточным при нулевой мутации, значит дело не в
том, что отбор не может найти путь, и крутить частоты мутаций бессмысленно.

## Счётная ферма на сервере

Стенд гоняется не только здесь. На биоинформатическом сервере (24 ядра) прогон
в 12 000 часов стоит **52 секунды против 250–400** в облачной песочнице, и матрица
из 60 прогонов считается четыре минуты вместо получаса. Доступ — через HTTPS-шлюз
`ssh-gate` (репозиторий `vvp310792/ssh_agent`): сырой SSH из облачной сессии не
проходит, обязательный прокси форвардит только TLS.

```
tools/run1.js     один прогон -> одна строка CSV, всё задаётся окружением
tools/cata.js     то же, но со сценарием резкой катастрофы (свет гаснет циклами)
tools/cata2.js    катастрофа + померы по КАЖДОМУ удару: глубина провала, время возврата
tools/farm.sh     матрица: строка задания -> прогон, N штук параллельно
tools/farm2.sh    то же, но скрипт прогона выбирается полем RUNNER= в задании
tools/farmrun.sh  ЕДИНСТВЕННЫЙ правильный вход: матрица + паспорт в архив
```

### Почему результат без паспорта бесполезен

Прогоны с разных коммитов несопоставимы даже при одинаковом seed — лишний вызов
генератора сдвигает весь случайный поток, и «тот же самый» контрольный мир даёт
2654 тела вместо 569. Поэтому `farmrun.sh` кладёт рядом с данными `manifest.json`
с коммитом, чистотой рабочего дерева, версией node, числом ядер и временем счёта,
а также точный файл заданий. Архив — на HDD (`~/claude_vvp/data/evolutioner`),
по правилу сервера «мелкое на SSD, крупное на HDD».

```bash
./farmrun.sh jobs_c3.txt покой_катастрофа "спасает ли покой от резкого удара" 24
```

### Зачем хранить прогоны

- **Пересчёт другой мерой.** Вымирание — редкое бинарное событие, и на двадцати
  прогонах оно не различает ничего; глубина провала по каждому из шести ударов
  за прогон различает. Сохранённый CSV позволяет задать новый вопрос, не
  пересчитывая.
- **Слияние выборок.** 20 + 30 + 90 прогонов одного условия дают точный тест там,
  где каждая серия по отдельности упирается в шум.
- **Проверка на снос баланса.** Базовая выборка на 90 миров с известного коммита —
  это эталон: после правки экономики достаточно пересчитать её и сравнить
  распределения, чтобы увидеть непреднамеренный сдвиг.

## Что этот стенд уже поймал

Дефекты, которые видны только на прогоне и не лечатся подбором коэффициентов:

- Хищник жил 4 часа: при переходе на общий пул тела потерялся стартовый запас
  из коррелированного пакета K-стратега. 379 рождённых, 379 умерших, ни одного
  дошедшего до добычи.
- Хищник без добычи в радиусе восприятия не двигался вовсе — `findNearest`
  возвращал null, и он стоял на месте до голодной смерти.
- Контур потомка центрируется на якоре; пока якорь брался вплотную к родителю,
  контур крупного плана всегда накрывал клетки самого родителя, и крупный
  организм не мог размножиться ни разу.
- Зазор между контурами считался по размеру родителя, а нужен по размеру
  ребёнка: для тела 4x4 контур идёт от -1 до +2 от якоря.
- Барьер определялся по всем восьми соседям. У правильного квадрата это верно,
  но у рваных форм клетки, окружённой своими со всех восьми сторон, не бывает
  даже в теле из 11 — дифференцировка не включалась никогда.
- Плотностный налог, поднятый с 0.02 до 0.035, утопил гетеротрофов: они по
  устройству ниши живут вплотную к чужим клеткам и платили этот налог всегда.
- Выздоровление от паразита, посчитанное как чистое `immunity*0.02`, означало
  625 часов болезни при стартовом иммунитете — то есть пожизненно. Мир падал до
  четырёх организмов; на глаз это выглядело как «паразиты слишком сильные», а
  дело было в отсутствии базового слагаемого.
- **Общий случайный поток сравнивает только то, что не меняет ЧИСЛО обращений
  к генератору.** `founderDiploid()` в одной из версий звал `founderGenome()`
  дважды даже в гаплоидном режиме — лишние вызовы сдвинули весь поток, и
  «тот же самый» контрольный прогон при том же seed дал 2654 тела вместо 569.
  Сравнивать можно только прогоны, снятые с ОДНОЙ версии кода; числа из разных
  версий не сопоставимы, даже если seed один.
- **Правка стенда во время идущих фоновых прогонов обесценивает их.** Каждый
  `node` грузит `sim.js` при старте, поэтому часть серии посчиталась по старому
  коду, часть по новому, а в выводе это никак не видно. Поймано по совпадению
  чисел: «контрольный» прогон дал ровно те же 470 тел и 111 сапротрофов, что и
  отвергнутый вариант, — при воспроизводимом seed это и есть подпись того, что
  считалось не то, что написано в метке. Правка кода — только между сериями.
- Имена переменных между `sim.js` и `index.html` РАЗОШЛИСЬ: в стенде свет это
  массив по строкам `vGrad`, в браузере после правки «свет равномерный» —
  скаляр `params.light`. Код всхожести семян, перенесённый копированием, дал
  `vGrad is not defined` и намертво остановил браузерную версию, тогда как в
  стенде всё работало. Переносить только сверяя имена.
- Разброс генов надо сравнивать с максимумом для равномерного распределения
  (1/√12 ≈ 0.289), а не с нулём: без этой опоры число «0.295» не значит ничего.

## Длина прогона — не больше, чем нужно вопросу

12 000 часов — рабочий размер почти для всего: к этому времени ниши сложились,
гены вышли на плато, и разница между условиями уже видна. 20 000 нужны только
там, где вопрос требует многих событий внутри прогона (шесть циклов катастрофы
по 3000 часов), и это единственное оправдание длинного прогона.

Цена ошибки прямая: 180 прогонов по 20 000 часов заняли 26 минут машинного
времени, те же 180 по 12 000 заняли бы вдвое меньше. Прогон, чей ответ ясен на
середине, — это выброшенное время, а не запас прочности.

## Сколько прогонов достаточно

**Вывод на четырёх прогонах — не вывод.** Поймано дважды подряд на одном и том
же вопросе: «покой спасает от вымирания» (2 спасения из 4 → на 60 прогонах
эффекта нет, p = 0.76) и «покой ускоряет восстановление» (p = 0.09 на 30 мирах
→ p = 0.16 на 180). При базовой частоте событий 20–40% четыре прогона не
различают ничего, и любая картинка в них — случайность.

Ориентир: для БИНАРНОГО исхода (вымер / выжил) нужны десятки прогонов на условие,
и даже 90 против 90 ловят только разницу в полтора-два раза. Для непрерывной
меры (глубина провала, средняя вирулентность) хватает 15–30 миров, потому что
каждый прогон даёт число, а не ноль-единицу. Поэтому первым делом стоит искать
непрерывную меру того же явления — это дешевле, чем добирать выборку.

## Две ловушки самого стенда

- Замер скорости, меняющий популяцию, не измеряет ничего: выключение фазы
  меняет экологию, и разница отражает число тел, а не цену фазы.
- Однострочный комментарий, дописанный в конец строки с несколькими вызовами,
  проглатывает следующие за ним. Так молча выключились `decayCorpses()` и
  `processSpores()`, а пятикратное "ускорение" оказалось двумя мёртвыми фазами.
